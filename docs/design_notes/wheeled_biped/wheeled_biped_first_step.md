# Wheeled Biped — First implementation step

This is the original implementation checklist, not the current implementation or validation status.
See the [formulation](../../wheeled_biped_whole_body_inverse_dynamics_mpc.md) and [handoff](../../wheeled_biped_handoff.md) for the current code and results.

**Milestone.** In flat-ground MuJoCo, use whole-body inverse dynamics MPC to balance Upkie on both wheels, track a small forward velocity, and brake to a stable stop. The controller commands effort on six joints: hip, knee, and wheel on each side. Start with ground-truth floating-base state and a fixed double-support schedule.

## 1. Bring up the six-actuator robot

- [ ] Import Upkie’s URDF and MuJoCo scene with its mesh assets. Add a Wheeled Biped robot configuration using the H2 launch and configuration paths as references. Map all six actuators by name and verify the left/right wheel signs with a small unloaded command.
- [ ] Convert the six MJCF servos to torque motors with unit gear and matching effort limits. Use the upstream caps of ±16 N·m per hip/knee and ±1.7 N·m per wheel as initial simulation limits. If the hardware interface adds PD to feedforward effort, check the cap on the summed command and set wheel position gain to zero.
- [ ] Reconcile the model used by the optimizer with the simulation. The checked upstream MJCF and URDF have masses of 5.4605 and 5.33922 kg and tire radii of 55 and 50 mm, respectively. Use the MJCF as the simulation reference. Match tire centers, radii, joint axes, and inertial parameters. Compare wheel-center poses and gravity torques at several configurations, and account for armature and passive forces when comparing dynamics.
- [ ] Keep unwrapped scalar wheel angles in the MPC state and mask them out of joint-position barriers and posture tracking. Keep wheel speed and effort limits. The upstream URDF wheels load as scalar revolute joints with zero default position bounds in the checked Pinocchio build. Changing both to URDF continuous joints produced 14 position coordinates and 12 velocity coordinates with the Jazzy root model, which conflicts with the current mapping.

## 2. Port the H2 controller to rolling contact

| Jazzy code to reuse | Wheeled Biped change |
|---|---|
| **WbIdDynamics**, **WbIdMpcRobotModel**, **WbIdRneaConstraintCppAd** | Keep the full-order state and RNEA residual. For the first port, retain two six-component wrenches at the wheel centers. Constrain each wheel-center moment to the moment generated by the contact force at the tire. Enforce both base and actuated RNEA rows over the full initial horizon. |
| **WbIdMpcInterface**, **WbIdFootAccelerationConstraintCppAd** | Replace planted-foot equalities and sole CoP constraints with rolling-wheel constraints. Keep unilateral normal force and friction. Use the tire center and axle to compute the instantaneous contact point. |
| **WbIdInitializer**, H2 effort output, H2 simulation launch | Start from an upright, slightly crouched pose with both wheels on the plane. Seed the optimizer from a static inverse-dynamics equilibrium with bounded torques. Use the existing ground-truth state input and effort output paths. |

For a first flat-ground model, let $p_h$ be the tire center, $\rho$ the offset from the center to the bottom of the thin-disk approximation, and $f$ the ground force on the tire. Set $m_h=\rho\times f$ and use wheel-center Jacobians in the RNEA residual. Enforce near-zero ground gap and near-zero tread slip. The slip velocity is $v_h+\omega_{\mathrm{wheel}}\times\rho$, where $\omega_{\mathrm{wheel}}$ is the full world-frame wheel angular velocity, including wheel spin. If using acceleration-level equalities, differentiate that entire velocity, including the configuration-dependent offset. Check equality rank in symmetric double support before adding every lateral no-slip row as a hard equality.

## 3. Run the first acceptance test

| Test | Pass condition |
|---|---|
| **Balance at zero command** | Both wheels remain in contact on flat ground. The torso and leg posture settle, and forward drift stays bounded. |
| **Recover from a small pitch disturbance** | The controller recovers upright balance without persistent slip or effort saturation. |
| **Roll, then brake** | Ramp to a small forward command such as 0.2 m/s, hold it, then ramp back to zero. Confirm the robot tracks the command and settles without losing either wheel contact. |

Log commanded and actual effort for all six joints, base pitch and velocity, each wheel’s normal force and tangential slip, and the solver’s dynamics and contact residuals. Use the measured contact data to confirm double support throughout the test.

Once this test is repeatable, use the same controller for a small symmetric hop by adding the flight phase. Then test a short single-support interval before scheduling alternating support (“trot”).

**Verification status.** The upstream MJCF was loaded and stepped in MuJoCo, the URDF was loaded in Pinocchio, and the Jazzy source paths were inspected. This checklist specifies the port and its acceptance test. The controller and torque-mode model changes still need implementation and closed-loop validation.
